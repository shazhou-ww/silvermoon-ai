# Deployment

这是未来现实世界验证的轻量种子，不是生产部署、npm 发布或生产数据操作授权。实施完成后，先同步细化部署契约，再在获准本地/隔离环境验证；目前没有运行或部署证据。真实目标宿主跨仓库接入不以本仓库夹具冒充。

## Steps

### D-S01: 明确分阶段启用与恢复边界

在获准环境中核对 Account/Device/Client 身份映射、历史保留、版本隔离、定向路由、账户群发入口、配额、权限和恢复路径，明确进入生产前需要的授权与可观测指标。

### D-S02: 验证真实网络双向闭环

使用获准的本地/隔离环境与账户，至少各建两个 Device 与两个 Client，加另账户对照主体。普通宿主嵌入 lib，薄 CLI 使用相同 API 连接 Device，不登记 Connector 实体；验证路由/群发、动态设备加入、独立恢复和显式接收确认，不接触既有生产设备与事件。

### D-S03: 验证兼容运行与受控恢复

验证旧历史读取、撤销权限、背压告警和恢复演练；若新版本已接收消息，禁止靠回退旧代码丢弃这些消息，需保留读取与补偿路径。

## Acceptance criteria

### D-AC01: 启用条件与数据边界可核验

以脱敏环境记录证明版本入口、Account/Device 归属、宿主嵌入的 lib/CLI 构建版本、授权与保留边界一致；实际启停/重开状态不产生第二套业务身份或丢失本地待同步消息。验证仅在约定环境开展，未满足条件不启用。

### D-AC02: 外部路由群发与自治有实证

以 Relay 自增 Message ID、目标/来源 Device、各 Client 已处理 ID 和脱敏交付矩阵证明：下行仅到指定 Device，上行全部同账户 Client 收到且不跨账户，新增来源/按 ID 补读无遗漏；同一请求键重试返回原 ID。HTTP 接收不冒充执行成功，Relay 离线时 Device 本地记录继续积累且恢复后同步。

### D-AC03: 历史与恢复无静默损失

以授权读取与恢复演练记录证明旧历史归属仍在、过期游标明确报错、撤销后访问终止，新旧版本恢复不造成消息静默丢失；不得记录凭证。
