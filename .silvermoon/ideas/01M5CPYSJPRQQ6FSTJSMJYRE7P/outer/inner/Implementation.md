# Implementation

这是准备阶段的可行性种子，不是本轮执行授权；构想验收不包含此契约。未来实施先收敛[设计待决项](ideal/Connection-and-Message-Design.md#待决事项)，再逐步细化，不预先指定物理 schema 或技术方案。

## Steps

### I-S01: 收敛协议与身份兼容

确定版本协商、身份映射、权限、幂等范围、fencing 与保留策略；以当前数据模型核实原 device/connector/stream 历史归属，形成可审查的兼容契约。

### I-S02: 接通双向持久链路

在明确的契约下实现双向提交、历史读取与实时交付，贯通 Supervisor 本地 outbox、持久 inbox/执行记录与游标；不以更换 HTTP 自动移除协调存储。

### I-S03: 验证故障与兼容边界

覆盖多客户端并发、重试冲突、双 Supervisor 抢占、离线恢复、未知副作用、背压、游标过期和授权撤销。保持现有 UI 行为；若实施需要改变屏幕或交互，先另行提供 ui-change-review 材料并请求相应决定。

## Acceptance criteria

### I-AC01: 身份与历史保持可归属

用迁移夹具证明凭证轮换、重连和重启不更换 Connector，旧命名空间历史仍可定位且不被重新编号合并；冲突映射明确阻断。

### I-AC02: 双向交付与执行语义可区分

通过集成测试证明先持久化再确认/通知、相同 ID 重试只记一次、冲突拒绝、断线可补读，以及 HTTP 接收与 Supervisor 接收/执行/完成相互独立。

### I-AC03: 故障与权限边界显式可见

用故障注入与授权测试证明旧 generation 被拒绝、跨账户不可访问、慢订阅不无限缓存、游标过期不静默跳过、未知副作用不盲目重放；运行受影响包既有检查并保存结果。
