# Implementation

## Steps

### I-S01: 识别重连后的历史缺口

在 connector 注册和 inventory 同步后比较每个可见 session 的本地活动水位与 Relay 已持久化水位，自动安排需要补偿的历史同步，并避免对未变化 session 做无界全量读取。

### I-S02: 协调补偿与实时事件

以稳定事件身份和顺序语义合并补偿批次、现有 Relay 事件与同时到达的实时事件；重试和重复连接必须收敛到相同结果，并保留信息更完整的事件版本。

### I-S03: 暴露同步完整性

记录补偿开始、成功水位和失败原因，使 API/UI 能区分完整、同步中与部分历史；读取失败不得删除已有事件或推进成功水位。

## Acceptance criteria

### I-AC01: 断线消息自动补齐

集成测试在 connector 离线时向既有 session 增加多轮历史，重连后无需浏览器触发即可在 Relay 读取全部新增事件，且顺序与设备一致。

### I-AC02: 重连与实时并发幂等

自动化测试覆盖重复 inventory、补偿命令重试、事件批次重放和补偿期间实时事件，证明最终事件集合无重复、无遗漏且丰富元数据不回退。

### I-AC03: 不可恢复缺口可诊断

测试令本地历史不可用或中途失败，证明 Relay 保留既有事件、不标记同步完成，并通过稳定状态和错误信息暴露部分同步。
