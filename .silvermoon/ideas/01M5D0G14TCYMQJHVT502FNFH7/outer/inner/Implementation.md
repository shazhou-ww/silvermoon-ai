# Implementation

准备阶段的轻量种子，不是本轮实施授权；构想验收不包含此契约。按[工作区行为契约](ideal/Device-Workspace-Design.md)逐步细化，保持已完成的协议构想和生产部署历史不变。

## Steps

### I-S01: 补齐 Client 工作区读取契约

核实账户 Device 枚举，补齐浏览器指定 Device 双向历史的只读接口与独立游标/鉴权；不借用 Device token/ACK，不新增配对实体，不把 v1 online 状态当 v2 在线证据。

### I-S02: 实现 Devices 与消息交互

实现账户上行视图、Device 双向消息及目标固定/必选的 JSON 发送、显式会话写入 opt-in、未知结果重试和有界缓存。保留 v1 历史、旧链接、设置与 `/legacy`，维持窄屏单面板导航。

### I-S03: 验证权限恢复与兼容

验证未授权/只读、空设备、网络中断、发送结果未知、游标过期、目标切换和旧链接。以组件/API/真实浏览器测试和受影响检查证明行为，不以静态评审 HTML 冒充实现。

## Acceptance criteria

### I-AC01: 路由与读取权限一致

用两个 Device、两个 Client 与另一账户夹具证明全部上行接收、Device 筛选不丢消息、下行只到指定目标，Client 双向历史只读且无 Device 消费权；页面/API 测试覆盖未授权与撤销。

### I-AC02: 消息交互状态可信

以浏览器测试证明有效目标/JSON/写权限缺一不可；原幂等键恢复未知提交，显示 Relay ID 而不冒充执行成功；重连/切换范围不静默跳过历史，未知在线状态如实展示。

### I-AC03: 视觉与旧历史兼容

桌面/窄屏验证全部评审场景、键盘导航和原始 payload 详情，旧 device/stream/seq 深链接仍定位原 v1 只读历史、`/legacy` 和设置可用；既有测试及受影响构建检查通过。
