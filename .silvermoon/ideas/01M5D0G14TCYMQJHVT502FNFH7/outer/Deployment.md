# Deployment

准备阶段的现实世界验证种子，当前没有运行或上线证据；不是生产操作授权。实现完成后先同步细化后的契约，再在明确获准的环境验证，不能改写此前仅后端上线的事实。

## Steps

### D-S01: 核对启用与授权范围

确定前后端同版本、目标环境、Client 只读 API 与写入 opt-in、旧历史入口和恢复路径；没有明确授权不部署、不创建或删除生产数据。

### D-S02: 验证真实浏览器消息闭环

在授权环境用隔离 Device/Client 证明账户上行、Device 双向读取和定向发送，检查桌面/窄屏、网络中断与明确的 Relay 接收反馈，不执行 payload 副作用。

### D-S03: 核验旧入口与保留数据

验证旧链接、v1 Streams 和 `/legacy`、账户/设备/token 设置仍可用，保留既有历史及试用设备；退出本次运行助手，脱敏记录结果与局限。

## Acceptance criteria

### D-AC01: 启用版本与权限可核验

用环境/部署版本与授权记录证明实际运行与同步契约一致，浏览器没有 Device 凭证和消费 ACK 权限，未授权主体拒绝读取或发送。

### D-AC02: 浏览器闭环与恢复有实证

以脱敏 Message ID/目标和浏览器观察证明所有来源上行可见、下行仅目标接收、未知发送可按原键恢复、接收与执行不混淆；桌面/窄屏场景均实际检查。

### D-AC03: 历史与清理边界保持

旧 device/stream/seq 链接仍打开原历史，原记录数量/归属无变更，`/legacy` 和设置可用；记录仅清理本次助手、不删除原数据且不暴露凭证的证据。
