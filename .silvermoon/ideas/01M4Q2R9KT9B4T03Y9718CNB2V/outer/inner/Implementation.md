# Implementation

## Steps

### I-S01: 分离 Relay 工作状态与执行状态

为账户拥有的 Session 增加持久化工作状态与受保护的状态变更操作，保留复合身份、消息历史及 Connector 的状态同步权限边界。补充迁移与旧客户端兼容性。

### I-S02: 提供完成与重新激活交互

增加 Mark completed、Reactivate 和 Show completed 入口；处理默认列表、筛选、父子上下文、当前选中项和离线状态。对仍在执行的 Session 明示完成不会停止 Agent；已完成项需重新激活后才可继续从 Relay 发送消息。

### I-S03: 验证状态与交互一致性

覆盖所有权、幂等更新、刷新/重连覆盖保护、跨浏览器一致性、失败反馈与桌面/窄屏交互；保留已结束、不可用、离线筛选语义。

## Acceptance criteria

### I-AC01: 状态边界可靠

数据库和 API 测试证明：旧 Session 默认未完成，Connector 同步不能覆盖工作状态，非所有者与已移除设备的 Session 无法更改，重复相同操作无额外副作用。

### I-AC02: 工作整理可逆且非破坏

自动化测试证明：完成与 Reactivate 保持同一 Session 身份和历史，不停止 Agent、不级联子会话、不解除原生归档，也不会因新事件自动重新激活。

### I-AC03: UI 状态和失败明确

桌面与窄屏浏览器验证完成、显示已完成项、查看历史和 Reactivate；持久化失败时不得显示虚假成功，选择与筛选保持连贯且键盘可访问。
