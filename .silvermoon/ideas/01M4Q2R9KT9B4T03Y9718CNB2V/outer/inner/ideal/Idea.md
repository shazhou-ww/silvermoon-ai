# 从 Relay 完成并重新激活 Session

## 问题

Relay 已支持独立的 Session 完成标记，但手机端列表动作的点击区偏小，详情页没有完成或 Reactivate 入口，用户必须返回列表才能整理当前工作。

## 结果

保留 Session 列表项右侧的小 glyph，并在桌面和手机的 Session 详情页顶部提供同样的完成 / Reactivate 动作；手机和触屏的点击区至少为 44 × 44 CSS px，不依赖 hover，不在会话正文增加大按钮。该标记仍属于账户下的 Relay 工作状态，与 Agent 执行状态独立，跨浏览器和设备保持一致。支持材料：[UI 对比](./ui-review/index.html)、[业务模型评审](./Business-Data-Model-Review.md)。

## 边界

- 完成不停止 Agent、不删除消息、不修改原机器的归档状态；已完成项先 Reactivate 再发新指令，恢复不自动发送消息或解除原生只读。
- 只管理当前账户拥有的指定 Session，设备仅离线时也可操作；已移除设备的历史保持只读，Reactivate 不恢复设备访问，父子 Session 不级联变更。
- 继续采用 Relay 独立标记；同步 VS Code/Copilot 原生归档不在本次范围。

## 验收标准

- 标记完成后默认日常列表隐藏该 Session；显示已完成项时可读取历史，并区分 Completed 与实际执行状态。
- Reactivate 后恢复为未完成；列表仍遵守已结束、不可用、离线等筛选，继续对话仍遵守现有能力和原生只读限制。
- 列表项右侧和详情页顶部均按工作状态提供完成或恢复图标；详情页可直接操作，无需返回列表，手机和触屏点击区至少为 44 × 44 CSS px。具备操作提示与键盘访问，两个入口的状态、进行中禁用和失败反馈保持一致；刷新、重连与跨浏览器读取不会被 Connector 的执行状态更新覆盖。
