# Implementation

本轮为问题登记，下列内容是可调整的轻量种子，不授权实现。

## Steps

### I-S01: 确认授权流程与账号选择方案

分别核实 Google、Microsoft、GitHub 的授权参数、已有登录状态下的行为和可支持的切换机制，不盲目复用同一参数；准备阶段使用 ui-change-review 创建说明性评审材料，实际检查三种流程的桌面、窄屏与取消场景。保留当前身份模型，不引入账号合并或绑定变化。

### I-S02: 实现获准方案并验证登录回归

仅在构想获准后修改必要的登录流程，为三种提供商分别补充账号切换、原账号登录、取消与适用授权校验的回归覆盖。

## Acceptance criteria

### I-AC01: 选择流程可用且不改变身份语义

通过定向测试与 UI 流程验证证明：三种提供商分别已有登录状态时仍可切换账号，取消可安全返回，原账号登录和身份归属保持正确。

### I-AC02: 既有授权校验保持有效

通过现有和新增定向测试证明各提供商适用的 state、PKCE、OIDC 校验及账号权限边界未被放宽；不保存身份、cookie 或凭据到仓库。
