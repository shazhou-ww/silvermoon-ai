# Implementation

实施候选基于已接受的 Ideal World，不修改其方向。恢复先前保存的实现后，与最新上游的输入请求、历史合并及登录布局整合；所有实施证据重新验证，不复用同步前候选的测试结果。详细技术边界见[连接确认契约](./Connection-Confirmation.md)，当前验证证据见[实施证据](./Implementation-Evidence.md)。

## Steps

### I-S01: 建立当前连接确认与结果归属

完善 Relay、协议与 adapter 的连接确认、观测顺序、执行可信度和可继续能力；保护新快照、未确认命令与独立历史同步，保持原业务身份。

连接建立立即替换当前确认上下文，注册通过 `confirmationVersion: 1` 启用。观测的连接身份与递增序号共同决定快照可更新性；当前 inventory 被更晚观测取代时保留新快照。元数据执行状态未知与明确可继续能力分离。实际交付前保存命令及原连接归属，已观测结果可补传但不重执行业务；显式状态/历史重试不能被旧未知任务阻塞。

### I-S02: 接入一致的列表与详情语义

实现离线菜单、关键词 AND 状态、facet 数量、分页、分组、空态与掉线草稿；保留上游输入请求等既有操作，并让它们遵守同一能力和连接门槛。

菜单新增离线选项，不混用 Gone；计数、分组与所有状态徽标使用当前确认。已打开会话保留 URL、正文、阅读位置与按设备/Session 隔离的草稿；离线或旧连接不展示实时等待输入面板，恢复确认后继续使用原面板。搜索/状态组合与分页不清除用户选择；读取错误不伪造空数据，失去访问不自动切换其他 Session。

### I-S03: 验证并记录兼容与回归

整合上游后执行针对性的协议、传输、Relay、adapter、Web 和浏览器回归；交叉核对业务模型及 UI 评审语义，记录实际通过的证据和升级限制。

执行内存迁移、完整工作区类型检查、lint、构建，以及浏览器桌面/移动/320px 场景；共享环境默认测试端口冲突时使用隔离端口，结束后移除临时配置。历史真实执行与包发布不属于本实施验收，不把 dry run 描述为部署。

## Acceptance criteria

### I-AC01: 连接与结果不会被旧观测误恢复

用 Relay/Connector 测试证明旧连接和低序号不能放行设备操作或回退状态；已观测命令结果可核对原归属，未知结果不伪造成功/失败、不重执行业务。

必须覆盖：实时观测与 inventory 交错、业务结果上传失败和执行中断连、旧连接错误归属拒绝、原命令结果补传、状态重试的真实 HTTP 路由与请求复用。证据为当前源码对应的自动化断言及测试结果。

### I-AC02: 过滤和掉线交互保持一致

用 helper 与桌面/移动/窄屏浏览器回归证明搜索和状态组合、离线 N、分组、空态、阅读位置和独立草稿；覆盖元数据未知状态但可继续、同步失败和失权，不回退上游输入请求交互。

同时证明输入问题/选项/自由回答原行为保留，离线及重连未确认阶段不展示旧等待输入操作，恢复当前确认后可继续；同步失败可主动重试但草稿不自动发送。既有滚动阈值、紧凑控件、登录页也须通过回归。

### I-AC03: 候选可构建且兼容限制明确

类型检查、lint、构建及迁移测试通过；验证旧 connector 的明确未确认状态和完整分页边界，记录不得用历史上传或活动时间替代当前确认的兼容要求。真实迁移与部署属于下游。

验证每设备超过 500 条的分页不遗漏或重复，保留每页既有 inputRequest 投影；旧 connector 可保留历史但不能默认为确认。所有 I 项的完成仅在后续证据真实通过后记录到 ledger，D 项仍未完成。
