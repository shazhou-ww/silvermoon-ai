# 通用事件同步实施契约

本文件按本轮讨论聚焦通用同步底座；原 Supervisor UI 与生产端接入不在本轮实施范围。具体实现必须满足下列验收，不以协议草案替代验证。

连接、消息原语与分包边界见[通用事件流同步技术方案](Event-Stream-Sync-Design.md)。草案中的未决实现细节由实施与评审收敛，必要偏差须记录理由。

实施结果、主 Agent 评审修复与独立验证见[实施评审与验证](Implementation-Verification.md)，具体使用方式见[同步说明](../../../../../docs/event-stream-sync.md)。

## Steps

### I-S01: 定义通用同步契约

新增独立且不依赖 Node/Cloudflare 或业务模型的 sync-protocol 包，定义身份、握手、原子追加、幂等、历史读取、持续订阅、确认与错误规则。复用现有协议校验工具，明确字段与资源限制及流内顺序。

### I-S02: 实现可靠接入与事件日志

在现有 Connector 中新增通用同步入口与可靠事件源接口，在 Worker 中新增按稳定账户/设备身份路由的 DO 同步模块。持久化日志、流头和必要写入隔离信息；实现补传、读取、订阅背压及重建恢复。保留旧 tRPC、Session 与公开包入口；不引入独立消息集群。

### I-S03: 验证故障恢复与兼容性

以真实 Node 客户端与 Cloudflare 本地运行时进行通用生产者/消费者集成验证，覆盖确认丢失、重复与冲突、源端缺口、重启、追赶期间写入、慢消费者、凭证撤销及隔离。运行适用回归、类型检查和构建；更新使用说明并保存可重现证据。

## Acceptance criteria

### I-AC01: 追加与恢复保持历史不变量

协议、Connector 与 DO 测试证明原子持久确认、连续序号、幂等追加、不同内容冲突、确认丢失补传和进程/DO 重建后的历史延续。源日志丢失或已裁剪历史不能静默跳过或重新编号；所有错误显式可见。

### I-AC02: 订阅连续且资源有界

测试证明历史追赶与新增事件之间无缺口、流内有序，消费确认只释放已交付窗口，重复确认不扩大窗口；限制帧、批次、连接和订阅资源。慢消费者可恢复，重建后恢复订阅或显式要求重订阅。

### I-AC03: 隔离兼容及真实链路成立

认证测试证明跨账户不可访问、撤销与设备移除阻止同步、旧连接不能继续写入；凭证轮换不改变流身份。旧 Session 回归及新公开入口的类型检查/构建通过；Node 与本地 DO 的真实 WebSocket 交互可重现。不发布 npm 包，不以静态夹具替代运行链路。
