# Deployment

用户已于 2026-10-12 授权继续 deployment。目标为 https://silvermoon.work，使用仓库既有 release 分支的 Check and deploy 工作流；不发布 npm 包，不改实现契约或产品代码。

## Steps

### D-S01: 在获准发布后验证浏览器体验

先同步本契约到 primary，并确认包含已验收实现提交 `14360ba6e1b6` 的交付快照。保留 release 的既有历史，在独立交付 worktree 中通过普通 merge 与非强制 push 合入已同步快照；再次核对产品差异仅属于该实现及既有文档/idea 元数据。如出现额外产品变更，暂停并明确范围。

由既有工作流检查通过后执行部署，保留 release commit、工作流 URL 和 Pages 产物引用；该流程也会运行既有 Worker 部署及 D1 migration 命令，本次没有新增后端代码、migration 或偏好服务。确认目标站点实际加载交付产物，再在已登录的测试账号中验证四项偏好跨刷新、重新打开、退出重登、账号切换及同账号多标签页。

### D-S02: 验证异常与既有体验

在目标站点分别以桌面和窄屏浏览器验证菜单、离线历史入口与分组恢复，并模拟存储读写受限，确认内联提示可见且开关、列表仍可用。验证仅操作测试账号的视图偏好，不发送 Session 指令、不创建设备或修改历史；保存并恢复验证前的偏好和视口。不得把模拟 API 或本地页面结果写成真实账号验证；缺少账号访问或外部证据时保留未完成条目并报告阻塞。

## Acceptance criteria

### D-AC01: 目标站点恢复与同步可观察

记录 release commit、成功的工作流与目标站点加载的资产引用，证明已验收实现实际交付。记录真实测试账号的浏览器验证结果，证明四项偏好跨刷新和重新打开保持，退出重登保留、账号间隔离、同账号标签页实时同步；不在仓库保存账号身份、Session 内容、cookie 或凭据。

### D-AC02: 降级可见且界面可用

以目标站点的桌面、窄屏和存储受限场景记录证明：内联提示可见、无横向溢出、开关和列表可操作、既有菜单与入口可用；恢复测试前偏好。证据放在本世界的 Deployment-Evidence.md，区分真实账号检查、公开产物检查和未完成项，不将本地测试或理想世界评审 HTML 当作生产验证证据。
