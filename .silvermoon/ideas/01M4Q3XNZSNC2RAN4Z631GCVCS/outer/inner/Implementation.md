# Implementation

本契约为准备阶段的轻量初版；具体 schema、兼容策略和改动范围在实施阶段按已接受构想细化。

## Steps

### I-S01: 固定协议与映射

把已接受的信道职责细化为版本化 schema、provider 能力映射和兼容规则，明确事件身份、顺序、覆盖范围、命令关联及显式缺失语义。

### I-S02: 贯通状态与命令链路

在 Connector、Relay 和 Web 消费链路中实现获准的 Session 状态与命令原语，保留旧客户端兼容边界；不实现第三信道的临时消息和订阅控制。

### I-S03: 验证恢复与跨 provider 行为

用针对性测试覆盖重复、重放、缺口、断线恢复、整 Session 缓存淘汰、回源不可用，以及命令结果与状态事实交错到达。

## Acceptance criteria

### I-AC01: 契约可追溯

通过 schema、源码引用和映射测试证明每个获准原语均有明确生产者、消费者与 provider 能力边界，且无未说明的默认映射。

### I-AC02: 历史恢复可验证

通过自动化测试证明重复与重放幂等、缺口不推进完整游标、整 Session 淘汰不伪装为完整历史，回源不可用返回显式结果。

### I-AC03: 命令语义保持独立

通过协议与集成测试证明命令接纳、RPC 结果和 Agent 状态事实可独立交错，旧客户端按记录的兼容策略继续工作，第三信道未被隐式实现。
