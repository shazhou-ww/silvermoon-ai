# Implementation

本契约为准备阶段的轻量初版；具体 schema、兼容策略和改动范围在实施阶段按已接受构想细化。

## Steps

### I-S01: 固定协议与映射

按下行请求共同细化输入、对应反馈、续推及失败边界，形成版本化 schema、provider 能力映射和兼容规则；明确 long poll 的观察基准、历史身份与连续覆盖、临时更新版本及显式缺失语义。

### I-S02: 贯通状态与命令链路

在 Connector、Relay 和 Web 消费链路中实现统一读取与操作反馈，支持 long poll 和可选的 Connector 有界续推；区分读取响应与后续通知，保留旧客户端兼容边界，不引入长期订阅状态机。

### I-S03: 验证恢复与跨 provider 行为

用针对性测试覆盖续拉/续推重叠、丢弃续推后补拉、等待超时、临时缓冲过期、断线恢复、整 Session 缓存淘汰及操作结果与事实交错；验证续推关闭时的正确性和窗口/流控边界。

## Acceptance criteria

### I-AC01: 契约可追溯

通过 schema、源码引用和映射测试证明每类获准请求及其反馈、续推与失败边界可追溯，有明确生产者、消费者与 provider 能力边界，且无未说明的默认映射。

### I-AC02: 历史恢复可验证

通过自动化测试证明重复与重放幂等、丢弃或关闭续推仍能按基准恢复、等待超时不改变基准、缺口不推进完整游标；整 Session 淘汰不伪装成完整历史，回源不可用与临时更新过期有显式结果。

### I-AC03: 命令语义保持独立

通过协议与集成测试证明操作接纳、RPC 结果和 Agent 状态事实可独立交错，读取响应后仍可识别续推通知，停止观察不终止 Agent；旧客户端兼容且续推资源在约定边界内释放。
