# Implementation

本契约为准备阶段的轻量初版，不代表实现授权。当前仅维护调查材料；如后续涉及产品变更，须先确定协议方向及实现范围。

## Steps

### I-S01: 核对协议与消费链路

按已接受的协议方向核对 Connector、provider 映射、worker 存储同步和 Web 消费；区分已有行为与必要变更，避免预设全面重写。核对事件身份、不可变历史、派生快照及命令关联边界，以 Ideal World 的业务模型评审为依据，不把讨论草案视为实现授权。

### I-S02: 验证获准范围

仅在用户明确授权实现后修改获准范围，并用针对性测试证明对应语义及兼容行为；如本期历史与 RPC 模型获准，覆盖重复、重放、断线恢复及命令结果与状态事件的交错，并验证整 Session 淘汰、不裁旧历史及回源不可用时的显式缺失。历史粒度不包含流式中间状态；第三类临时实时消息及其订阅/取消订阅仅记录后续 TODO，不在本期实现或验证其控制状态机。

## Acceptance criteria

### I-AC01: 行为与契约可追溯

获准范围内的协议语义可对应到实际实现和针对性测试；通过源码引用与测试结果证明，无未说明的 provider 映射差异。事件的身份、顺序及重放结果与获准模型一致，命令结果不被误判为 Agent 执行完成。

### I-AC02: 未授权范围保持不变

通过候选变更清单证明未修改无关产品行为、未擅自改变协议版本或发布包。
