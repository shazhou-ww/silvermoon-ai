# 事件流工作区外部验证初版

用户已明确授权主 Agent 负责技术门限批准、subagent 实施与部署，并要求交付线上环境供用户后续亲自验收。先在隔离本地环境验证，再通过既有 release 工作流上线 Web/Worker；不发布 npm，不写入或删除未知生产数据，不将技术上线确认冒充用户使用体验验收。

## Steps

### D-S01: 准备真实浏览器验证环境

同步稳定部署契约，记录 Web/Worker 版本、现有 release tip、所需 DO/D1 兼容迁移及回滚边界；使用隔离账户、测试凭证和真实通用事件生产者完成上线前验证。审查并保留并发 release 历史，仅以普通非强推方式交付已审实现，不暴露部署凭证。

### D-S02: 验证跨设备读取与恢复

在隔离环境用真实 Node 生产者向两个逻辑设备发布多个流，登录浏览器查看历史、定位和跟随；用大量历史及长 payload 验证虚拟行、缓存和回读，覆盖连接中断与恢复。通过既有 release 工作流部署已审版本的 Worker 与 Pages，等待检查、迁移和部署完成，核对线上资产及接口版本，不以 main 合入代替上线。

### D-S03: 验证授权与管理并收尾

本地验证另一账户不可读取、会话失效与设备移除终止访问，回归设备/token 管理及旧 API。线上只做授权范围内的只读检查，包括页面、健康、登录入口、未授权 API 和来源拒绝；若无可用的已登录验收账户，不绕过登录或种入生产身份，明确把登录后的体验交给用户。记录线上 URL、精确版本、检查结果和安全的通用生产者启动步骤，清理自有验证进程与临时数据。

## Acceptance criteria

### D-AC01: 真实工作区可复现

保存真实 Node/浏览器/DO 本地证据及生产工作流 run、release SHA、Worker/Pages 部署结果；线上 URL 和资产对应已审版本，不是静态评审或仅本地实现。提供无需发布 npm 的通用事件生产者启动方法，不将旧 AHP Session 自动冒充流。

### D-AC02: 状态与恢复符合约定

本地实际断线和恢复证据显示位置与跟随连续；大量历史的 DOM 行数、缓存条数及 payload 字节符合实施门限，桌面与窄屏沿用原结构，内容不作为 HTML 执行。线上页面与接口可达且未授权访问明确被拒；有合法登录环境才进行对应线上账户读取，不以本地证据宣称生产身份已验证。

### D-AC03: 访问管理与交付边界成立

授权、管理及旧接口的回归通过；生产部署检查成功、回滚边界明确，验证进程与临时数据完成安全收尾。向用户提供线上验收入口、数据准备与步骤，并明确待其亲自确认的登录后体验；不得代记用户最终使用验收或 npm 发布。
