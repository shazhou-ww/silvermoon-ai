# 事件流工作区外部验证初版

默认先在隔离本地验证环境交付；生产上线需要明确版本和授权，不因创建此 idea 自动部署 release 或发布 npm。

## Steps

### D-S01: 准备真实浏览器验证环境

同步稳定部署契约，记录 Web/Worker 版本及授权测试环境；使用隔离账户、测试凭证和真实通用事件生产者，明确本地或生产范围，不读取未知生产数据。

### D-S02: 验证跨设备读取与恢复

真实 Node 生产者向两个逻辑设备发布多个流，登录浏览器查看历史、定位和跟随。使用大量历史及长 payload 验证默认表格的虚拟行、缓存边界与跨页回读。主动断开/恢复生产端和浏览器连接，证明位置延续、离线历史与实时状态可辨；无生产者时显示空状态。

### D-S03: 验证授权与管理并收尾

验证另一账户不可读取、会话失效与设备移除终止访问；回归设备和 token 管理及旧 API，保留脱敏结果、回滚边界并清理操作拥有的验证进程及临时数据。

## Acceptance criteria

### D-AC01: 真实工作区可复现

保存环境、精确版本及脱敏浏览器证据，证明读取的是已持久化 DO 事件，不是静态评审、mock API 或将旧 Session 伪装的新流。

### D-AC02: 状态与恢复符合约定

实际断线和恢复的浏览器证据显示离线历史、处理位置、重新跟随与错误提示；大量历史下记录 DOM 行数、缓存条数与 payload 字节，符合实施契约的数值边界。桌面和窄屏沿用原清单/详情结构且能完成主流程，显示内容不会执行为 HTML。

### D-AC03: 访问管理与交付边界成立

真实账户隔离、登录失效和设备移除验证通过，管理功能及旧接口仍可用；验证进程和数据完成安全收尾。明确线上是否交付，不能用本地通过声称生产上线。
