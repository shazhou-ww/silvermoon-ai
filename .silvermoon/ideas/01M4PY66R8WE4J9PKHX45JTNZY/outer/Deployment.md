# Deployment

## Steps

### D-S01: 准备兼容发布与验证环境

用户已授权持续实现至线上验收，不单独进行实施人工验收。目标为生产环境 `relay.silvermoon.work` 与 `silvermoon.work`，复用 `release` 分支的 Check and deploy 工作流：先通过完整检查、浏览器回归和本地全迁移，再应用 D1 `0011_device_management.sql`、发布 Worker、发布 Pages。无需发布 Connector 包。

迁移仅增加状态列及一致性触发器，不物理删除历史，也不修改现有设备状态。发布或回退均保留迁移、撤销记录和移除标记；优先向前修复，不通过清空 `removed_at`、恢复 token 或删除迁移回滚。新旧前端交替期间服务端拒绝已移除身份，旧 Worker 的迟到历史写入仍被数据库阻止。

仅使用明确新建、名称带 `device-management-verification` 前缀的专用测试设备，记录操作产生的 ID 后才允许重命名或删除；不操作现有真实设备，不读取、输出或提交 token 明文，不直接编辑生产数据库。浏览器登录缺失时请用户在部署阶段登录，不能绕过身份校验。

### D-S02: 发布并验证外部行为

通过普通非强制 Git 更新 `release`，保留其他 session 的发布历史；记录实际提交和 GitHub Actions 链接，确认迁移、Worker 与 Pages 三项均成功，然后检查生产站点与未登录 API 的权限边界。

在已登录浏览器中，用上述专用在线和离线设备验证重命名、删除、旧 token 重试、只读历史和重新添加，并检查实际 Connector 的断线重试与提示。测试 Connector 只允许合成会话，不能将现有本机会话作为验证输入。验证其他设备和已有历史不受影响；证据如实区分 CI、本地集成、公开生产探测和登录后的端到端验证，不以匿名健康探测替代用户结果。

## Acceptance criteria

当前生产发布及探测见 [Deployment-Evidence.md](./Deployment-Evidence.md)；该证据明确区分发布成功和登录后用户结果，不能以 CI 或匿名探测代替 D-AC02。

### D-AC01: 发布与兼容边界可证明

记录实际环境、组件版本、迁移结果及兼容检查，证明新增迁移不改既有设备身份、所有权和历史归属，回滚方案不会复活旧凭据。不得记录 token 明文。

### D-AC02: 用户结果端到端成立

通过专用设备的浏览器操作、Connector 日志及授权的只读数据核对，证明在线/离线设备可移除、旧凭据被拒绝、历史仍可读不可发送、新设备身份独立；保存桌面/窄屏证据，并确认使用说明准确区分 Relay 断开与本地 agent 运行。
