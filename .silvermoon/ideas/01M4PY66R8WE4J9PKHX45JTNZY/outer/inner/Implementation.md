# Implementation

## Steps

### I-S01: 建立设备管理与生命周期一致性

复用账号所有权与 CSRF 校验、token 撤销、连接身份校验及批处理机制；以 Device 为名称权威，同步 Connector 显示投影。引入保留身份的移除语义，覆盖全部 token 与连接入口、轮换、注册、命令和事件写入，处理并发竞争及旧数据兼容，避免级联清除历史。

### I-S02: 接入设置操作与历史展示

实现重命名保存/取消、删除确认和明确的加载/错误状态，更新所有名称消费面；区分正常设备清单与历史来源，使已移除设备历史仍可发现和只读查看。保留可访问性、焦点恢复及窄屏操作能力，不以缓存移除代替后端完成。

### I-S03: 验证边界并更新说明

增加针对在线/离线、全 token、并发轮换/重连/迟到写入、账号隔离、在途命令与重新添加的测试；核对现有重连、轮换和历史查看行为。更新直接相关使用说明并记录可复现证据，实施阶段再细化必要工作。

## Acceptance criteria

### I-AC01: 名称与身份保持一致

用 API 和界面测试证明名称规则沿用去首尾空白、1–80 字符及允许重名；设备与 Connector 名称一致，ID、token、Session 不变，重连不会覆盖新名称。检查设置、标签、分组、搜索和设备选择。

### I-AC02: 移除不会重新获得访问

用 Worker 集成测试证明所有者操作、CSRF 与跨账号隔离有效；在线/离线及竞态下，全部关联 token 被禁用，旧连接不能发送命令或写入历史，重连和轮换不能复活设备，其他设备不受影响。未发送命令明确失败，已发送未确认结果不冒充取消成功；断开失败有可见且可重试的结果。

### I-AC03: 历史保留且交互可用

通过持久化断言与浏览器桌面/窄屏验证证明 Session、事件、命令历史及原归属保留，已移除历史可发现并只读，正常 Devices 和新建选择排除已移除设备。验证确认、取消、保存失败、删除中与删除失败、键盘和焦点行为；相关构建、类型检查及最小回归测试通过。
