# Settings 导航与 Session 草稿行为草案

状态：本 session 已授权实施的行为依据；代码候选仍需实施验收，Silvermoon 精确 revision 的正式方向接受尚未记录。

## 1. 导航目的地

| 目的地 | 地址 | 行为 |
| --- | --- | --- |
| Session / 默认工作区 | `/?connector=device-id&session=session-id` | 兼容现有链接；无选择时沿用现有默认列表和选择策略 |
| 总 Settings | `/settings` | 登录后独立打开右侧配置页，无会话也可访问 |
| 有返回上下文的 Settings | `/settings?connector=device-id&session=session-id` | 参数仅记录返回会话，不同时显示会话内容或标亮该列表项 |

- 用户选择不同目的地时推入浏览器历史；重复点击当前目的地不制造重复历史项。前进、后退切换实际页面，而不是仅改变地址。
- 保留现有有效会话 URL。上下文不存在或不可访问时不悄悄显示另一会话；用户通过桌面列表或窄屏抽屉选择其他会话。
- 页面刷新、复制地址和直接访问均显示相同目的地；实现时验证静态站点 `/settings` 的 SPA fallback，不以开发服务器正常作为生产直达的替代验证。
- 账户菜单 Settings 及左侧 Devices 计数入口进入同一路由；后者定位现有 Devices 卡片，不新增设备专用页面或路由。
- 未登录直达 Settings 时使用现有登录页；登录入口携带同站点 `returnTo`，成功后返回 Settings。身份绑定同样带回 Settings 的 `returnTo`，不改变服务端身份归属或 OAuth 安全规则。
- 首轮不新增 Settings 分类、第三栏、全局设置图标或新配置功能。

## 2. 页面与返回

- 桌面顶栏：Settings 标题和已确认的单一账户头像入口；没有关闭弹窗的 X，也没有 Back to Session / Back to Sessions。
- Settings 统一单纵列，合并 Add device 与 Devices，模块顺序为 Devices、Linked identities。Browser sessions 管理界面明确移除。
- 模块内部横向分配信息与操作：设备名在左，Agent / Session 数居中，状态和 token 操作在右；身份名称及账号在左，Unlink 在右。窄屏允许必要换行，不要求所有内容纵向堆叠。
- 桌面：保持 Session 列表、搜索、筛选及层级的现有规则；Settings 期间无 Session 当前选中高亮。点击任一会话进入该会话。
- 桌面直接点击左侧会话离开 Settings。窄屏配置内容独占主区域、卡片单列，顶部只增加列表图标，点击展开 Session 导航抽屉，不使用文字返回按钮。
- 抽屉复用现有 Session 列表、搜索、筛选及层级状态，不新增状态规则或列表副本。关闭按钮、Escape 或遮罩关闭抽屉时仍留在 Settings，并恢复列表图标焦点；点击会话后关闭抽屉并进入该会话。
- 抽屉使用模态导航语义、明确的 Open Sessions / Close Sessions 可访问名称和焦点约束；打开时聚焦抽屉内部，背景不可交互。切到桌面尺寸时关闭抽屉并恢复常驻列表，不改变当前路由或草稿。
- 抽屉开合不生成独立路由历史；浏览器前进 / 后退按已有页面历史切换路由。应用内会话选择直接进入目标路由，不调用 `history.back()`。
- A → Settings → A：同一页面运行期间保留 A 的阅读位置及是否跟随最新；正在读历史时不跳底部，原本跟随最新时返回最新，继续沿用 64 CSS px 阈值及 Jump to latest。
- A → B → A、刷新、首次打开会话：沿用已有打开会话定位最新的行为。本期不实现跨会话或跨刷新阅读位置缓存。
- 路由变化后焦点进入页面标题，不自动聚焦输入框或弹出软键盘。账户菜单保留键盘开合、可访问名称、Escape 关闭及未导航关闭时的焦点恢复。

## 3. 独立输入草稿

### 已确认结果

- A、B 各有独立输入。A → Settings → B → A 不丢失 A 草稿，也不把 A 草稿显示在 B。
- 当前标签页刷新后恢复；不要求浏览器重启后长期保留。

### 存储与清理

- 使用当前账户用户 ID、connector ID、Session ID 组合隔离；不以标题或浏览器登录 session ID 代替领域身份。
- 首轮只缓存现有 Session 的 follow-up 输入，不扩展到新建会话表单、设置表单、阅读历史或 connector profile。
- `sessionStorage` 与内存状态配合，不上传草稿。普通切路由不清理；空输入删除对应草稿。
- 存储不可用、容量不足或数据损坏时明确展示“草稿未能缓存，当前页面仍可编辑；刷新可能丢失输入”。保留有效内存输入，允许用户继续编辑，不宣称保存成功。
- 浏览器标准标签页恢复或复制可能恢复 / 初始化存储副本，不承诺严格关闭即销毁或不同标签页初始内容绝对隔离；复制后独立编辑，无跨标签页同步。
- 账户菜单 Sign out 成功或确认认证失效时清理本标签页当前账户的草稿和临时敏感展示；清理失败明确通知，不能让新账户看到旧账户草稿。退出登录请求失败不清除草稿。不使用 `sessionStorage.clear()` 清理无关存储。
- 因离线、归档、筛选隐藏等现有状态暂时不能发送，不删除草稿，也不改变发送权限或列表默认策略。

### 发送期间

- 提交时固定源账户 / 设备 / Session 和草稿版本；切去 B 或 Settings 不能让 A 的响应修改 B。
- 请求提交期间、命令等待期间均保留提交文本。沿用现有命令流程和发送限制，不新增自动重试。
- 请求失败、命令失败或状态无法确认时保留源草稿并展示原有错误 / 状态；只有命令明确成功，且源草稿未被后来编辑时，才清除对应版本。
- 用户提交后又编辑了新内容，则成功回执不清新内容。设置操作也不能清理 Session 草稿。
- 刷新后无法确认此前提交状态时保留草稿并提示先检查消息流，不自动重发，不把“草稿恢复”当成“投递失败”。

## 4. 配置操作与一次性 profile

- Devices 面板顶部提供 Add device 入口。默认不显示输入，点击后在面板内 inline 展开 Device name 和 Expires in days；复用现有字段、默认值及验证，不新开创建弹窗。
- 创建表单插入设备列表条目区域，与现有设备条目同级、同宽、同对齐，沿用行间分隔；不增加嵌套 panel 或独立表单卡片。输入框本身保留正常的字段边框。
- 宽屏两个输入与 Add device / Cancel 操作同一行，操作靠右；窄屏输入逐行排列，操作仍独立成组。不把模块单列布局扩展为条目内全左侧纵向布局。
- 未提交时 Cancel 只取消创建并收起表单，不发请求、不修改设备列表；建议丢弃尚未提交的表单值，再次展开使用既有默认值。输入示意使用代表性数据，不代表改动默认值。
- 创建提交中显示处理中并禁用重复提交；此时 Cancel 不执行取消请求。创建成功后收起表单、更新设备列表，在 Devices 模块展示一次性 profile；失败时保留表单和输入并显示错误。新输入草稿缓存只针对 Session，不缓存该设备表单。
- Add device、Devices、Linked identities 保留既有字段、操作和权限限制，包括至少保留一个登录 provider、只读会话及 token 轮换 / 撤销。
- 移除 Browser sessions 面板、逐项撤销及重复的 Sign out here，不新增批量退出操作；当前浏览器统一通过账户菜单的 Sign out 调用现有 logout 流程。
- 前端不再为已移除的管理 UI 加载 `/api/sessions` 列表，也不调用其他浏览器撤销入口；保留服务端认证记录、cookie、CSRF 与兼容 API，不做数据库迁移。
- 服务端目前登录有效期为 30 天，最多 20 个有效登录；这两个规则保持原样。删除管理入口后，不提供从当前浏览器远程释放其他登录的 UI；上限恢复依靠其他已登录浏览器退出或登录过期，不自动撤销任何登录。
- Settings 中创建 / 轮换 / 撤销 / 解绑 / 复制等结果，在当前页可见地反馈；不能因通知落在被遮挡区域而无声失败。现有新建 Session 弹窗不在本次改造范围。
- 完整 connector profile 仅在当前 Settings 访问期间临时展示，复用 Copy profile、Hide；旁边明确提醒“离开 Settings 或刷新前请复制，之后不会恢复”。
- 离页、Hide、刷新或退出登录清除完整 profile；不放入 URL、草稿、历史状态或本地持久化。离页后的迟到响应不重新披露敏感值，也不作用于新账户。
- 不将“已生成”当作“已复制”。若生成期间离页，token 可能已创建或轮换，但不再展示该响应；回到 Devices 可用现有 Rotate token 取得新凭据，不自动重复操作。

## 5. 实施后需要验证的结果

| 场景 | 必须观察到 |
| --- | --- |
| 桌面 / 窄屏账户菜单 | 图标入口；信息仅在菜单顶部；Settings 和 Sign out 可键盘操作 |
| 窄屏 Session 抽屉 | 图标可访问；键盘打开、Escape / 遮罩关闭、焦点恢复；选会话后关闭并导航；桌面不显示抽屉 |
| 两个 Settings 入口、登录 / 绑定返回 | 进入同一配置页；Devices 入口定位卡片；同站点 returnTo 生效 |
| 直接打开 / 刷新 / 前进 / 后退 | 目的地与 URL 一致；生产静态站点可直达 `/settings` |
| A → Settings → A | 草稿保留；历史阅读不跳底；原本跟随最新继续跟随 |
| A 输入 alpha → B 输入 beta → A | A 是 alpha、B 是 beta，Settings 中无会话输入框 |
| 同名或同 ID、不同设备 / 账户 | 草稿互不串用；登出和认证失效不会泄露旧账户输入 |
| 刷新及存储故障 | 刷新恢复；故障明确提示，当前输入仍可编辑 |
| A 提交后切到 B / 编辑 A | 失败保留；成功仅清源版本，不清 B 或新输入 |
| profile 展示后离页、返回、迟到响应 | 不持久化、不重新披露；复制失败明确可见 |
| Devices inline 创建 | 默认收起；创建条目与设备条目同级同宽，不嵌套 panel；两个既有输入；Cancel 无请求；创建成功收起，失败保留 |
| 简化浏览器管理 | Settings 无 Browser sessions 面板或远程撤销；账户菜单 Sign out 只退出当前浏览器；不再请求管理列表 |
| 基线回归 | 设备及身份操作、Session 列表、归档 / 离线权限、消息定位及后端鉴权规则保留 |

当前 HTML 仅验证说明性布局和少量评审交互，不证明生产行为已经通过；实施验证记录归属于主体世界，不由设计稿代替。
