# Implementation

实现基于提交 `74560a2`，构想验收后已重新复核和验证；本契约及
[实施证据](Evidence.md)是本次实施验收候选，不代表真实发布完成。
发布操作与安全边界见[发布指南](../../../../../docs/npm-package-releases.md)。

## Steps

### I-S01: 复核发布机制

根据参考仓库实际方式及当前公开包清单，复核 tag、版本、认证、安全边界和重复执行行为。
只允许 `npm/connector/v<version>` 且版本精确匹配 manifest；稳定版使用
`latest`，具名预发行使用对应频道。发布 commit 必须可达刷新后的主线，
重复版本明确失败；沿用 npm environment 和 Trusted Publishing，不增加自动 tag 或定时发布。

### I-S02: 验证输出包

复核构建、发布契约测试和实际 tarball 的独立安装，保留私有运行时与声明内联保证。
工作流对已构建包只 pack 一次，验证包内容及完整性、完成外部安装 smoke，
再复核 SHA-256 并发布该 tarball，最后核对 registry 字节及 dist-tag。

### I-S03: 完善维护说明

使触发规则、一次性配置、失败恢复和验证边界与实现保持一致，并记录必要实施证据。
说明 tag 和主线保护属于外部信任边界，PR 无发布入口；并发不取消运行中的发布，
已发布版本的重跑不发布也不改频道。部署初版保留独立首发授权与外部验证门槛。

## Acceptance criteria

### I-AC01: 发布指令有明确边界

通过契约测试及工作流检查，证明只接受 allowlist 中包的匹配版本，错误 tag 和已存在版本明确失败，且不向 PR 授予发布权。

### I-AC02: 包可独立消费

类型检查、相关测试和构建通过；对实际 npm tarball 执行私有导入检查、干净安装、CLI 与公开导出及消费者类型检查。

### I-AC03: 操作说明完整

以实现对照发布指南，确认 registry、权限、OIDC 配置、并发及重试行为均有说明，且不将本地验证描述为真实发布。
